# Чек-лист CL-02 — Items

| Поле | Значение |
|---|---|
| Модуль | Items: F-06…F-10 из [Test Plan](../TEST_PLAN.md) |
| Эндпоинты | `POST /items/`, `GET /items/`, `GET /items/all`, `PUT /items/{item_id}`, `DELETE /items/{item_id}` |
| Версия продукта | API v1.7.0 |
| Окружение | Local (Docker), `http://localhost:8000` |
| Исполнитель | |
| Дата прогона | |

**Легенда:**
- **Приоритет:** H — High, M — Medium, L — Low
- **Статус:** ✅ Passed · ❌ Failed · ⚠️ Blocked · ⏭ Skipped
- **❓** — требование не задокументировано явно; ожидаемый результат основан на общепринятой практике, при расхождении завести вопрос / баг
- **R-xx** — ссылка на зону риска из Test Plan

**Предусловия для всего модуля:**
1. Стенд запущен, `GET /health` → `200`.
2. Лимиты `ITEMS_READ_RATE_LIMIT` и `ITEMS_WRITE_RATE_LIMIT` увеличены в `.env` до `1000/minute`. Rate limit проверяется отдельно, в [CL-03](CL-03_RateLimit.md).
3. Есть два залогиненных пользователя: **User A** (`{{token_a}}`) и **User B** (`{{token_b}}`). Все запросы — с `Authorization: Bearer <token>`, если не указано иное.
4. Для проверок пагинации: БД items очищена (`docker-compose down -v` или `DELETE FROM items;`), затем создано **25 items** (15 от User A и 10 от User B).
5. Состояние БД проверяется запросами вида `SELECT * FROM items WHERE id = <id>;`.
